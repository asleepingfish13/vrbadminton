# Vive Shuttle VR / 小空间原地羽毛球训练

> 当前 `main` 分支保存已验证的自动发球训练版。175 cm 虚拟身高、100 ZZ 参考球拍、AI 对手及标准球馆的进行中修改位于 `development/astrox-ai-height` 分支，尚未完成整体验证。详见 [开发进度](Documentation/Progress.md)。

独立 Unity 项目，原来的 HTCViveThrowDemo 不变。这一版是单人自动发球练习，支持握把基准球拍、挥速驱动出球和技术动作提示；不是完整双人比赛、科研级模拟或专业动作评估工具。

## 启动

1. 启动 SteamVR，确认 HTC Vive 头显和至少一只手柄已连接。
2. Unity Hub 添加本目录，用本机 **Unity 2020.3.0f1** 打开。
3. 打开 `Assets/Scenes/ShuttlePractice.unity`，点击 Play（也可以在编辑器按 F8 打开场景）。
4. **在已清空的活动区域站稳或坐稳，看向希望的球场正前方，不要转头去找发球机**。按惯用手的**扳机**，球场会以此刻头显朝向为正前方重新对齐，然后开始发球。启动提示会出现在视线前方。
5. 默认混合来球：发球机按平衡顺序交替送出五类轨迹，薄荷绿圆环指示本球预计击球点。握着手柄小幅挥动球拍击球，不需要按住扳机。

如果已有 `Build/Windows/ViveShuttleVR.exe`，也可先开 SteamVR，再直接运行它，无需把它添加到 Steam 库。编辑器与独立游戏不要同时处于 VR 运行状态。

## 控制

| 操作 | 功能 |
| --- | --- |
| 扳机 | 每轮首次开始时，对齐当前正前方并开始；回合中暂停后的继续不改变朝向。哪只手按下，来球就偏向哪一侧 |
| 挥动手柄 | 挥拍击球；两只手都可持拍，击中有震动和声音；轻挡不要求最低挥速 |
| 侧握键 | 暂停 / 继续 |
| 菜单键 / 键盘 R | 按当前视线重新定位球场，并清零本轮 |
| 键盘 Space / P | 开始 / 暂停 |
| 暂停且无球飞行时点击触控板下方 | 循环选择训练模式 / 磅数 / 克重 / 固定或混合来球 |
| 触控板左 / 右 | 调整当前选项；磅数每次 1 lb、质量每次 0.1 g |
| 键盘 [ / ]、- / = | 分别减 / 加磅数、克重 |
| 键盘 M / Backspace | 切换固定或混合来球 / 恢复 25 lb、5.4 g |
| 暂停时点击触控板上方 / 键盘 A | 开关坐姿辅助，不自动瞄准或抬球 |
| 暂停时键盘 1 / 2 / 3 | 分别选择正手对拉 / 头顶球 / 网前球；重置本轮 |

以上设置只在暂停且没有飞行中的球时可改。若已暂停空中球，先用菜单键 / R 明确重置本轮再调整，避免同一球中途改变物理。切训练前先站稳或坐正、看向希望的球场前方。切换后按扳机开始。键盘操作需要游戏窗口获得焦点。

没有头显时可做桌面逻辑测试：Space 开始，球接近绿色圆环时单击鼠标；鼠标横向位置控制模拟拍面的方向。鼠标采用固定模拟挥速，不能用来验证真实手柄的握拍角度或挥速响应。

## 正手握拍与角度微调

球拍现在以控制器的 **OpenXR grip pose（握把姿态）** 为基准，不以用于指向菜单的 aim pose 为基准。移除了旧版任意固定的 50° 倾角，模型握柄中心与追踪握把原点重合。模型从握柄中心到拍头中心的长度约为 36.5 厘米。

OpenXR 定义的握柄方向在 Unity 坐标中对应局部 +Z；模型原有的 +Y 拍杆沿此方向放置，拍面法线放在 grip +X，作为正手“握手式”握拍的初始映射。左右拍面都可击球。这是坐标基准与可调初始握法，不代表每个人的实际握拍角度完全相同。

如仍觉得拍面有少量偏差，在 Unity 非 Play 状态选中 `XR Origin` 下的 `Left Racket` 或 `Right Racket`，调整 `Racket Controller`：

- `Grip Position Offset`：相对追踪握把的位置微调，单位米，默认零。
- `Grip Rotation Offset Euler`：绕握把局部轴的旋转微调，单位度，默认零；不需要重新填入旧版的 50°。
- `Model Grip Center`：当前模型握柄中心，默认 `(0, 0.035, 0)`，通常不必改。

每次小幅调整后试打并保存场景；Play 中的临时 Inspector 修改通常不会在退出 Play 后保留。左右手可分别设置，不会改变头显方向或整个球场朝向。

坐标依据：[Khronos OpenXR 标准握把姿态](https://registry.khronos.org/OpenXR/specs/1.1/html/xrspec.html#semantic-path-standard-pose-identifiers)、[Unity 的 OpenXR 坐标转换说明](https://docs.unity.cn/Packages/com.unity.xr.openxr@1.17/api/UnityEngine.XR.OpenXR.NativeTypes.XrPosef.html)。项目本地 OpenXR 1.0.2 的 HTC Vive Controller Profile 将 `devicePose` 明确绑定到 `/input/grip/pose`。

## 挥速、出球与技术动作

出球由接触瞬间的相对速度、拍面方向、击中位置、恢复系数和摩擦冲量决定，**不再根据目标落点反推回球轨迹，也没有自动抬球或自动瞄准**。发球机仍会计算送到练习圆环附近的发球，这与玩家击球后的自由飞行是两件事。

- 拍头速度同时包含握把平移和手腕转动：`拍头速度 = 握把速度 + 角速度 × 拍头偏移`。接触点不在拍头中心时继续计入该处的旋转速度。
- 实现上用同一段前后帧拍头世界位置/旋转计算扫掠与接触速度，拍头位移已经包含手腕转动；不再让另一时刻的设备速度覆盖。接触法线由球在拍面的实际哪一侧决定，分离中的接触不通过翻转法线强行击中。旋转拍面使用接触时刻的角度，保持双面击球能力，不把出球强制转向球场前方。
- 来球、拍面和击中位置相同时，向球正面挥得越快，通常出球越快；很快的切向“刷球”会更多体现为旋转，不能只看总挥速判断出球快慢。
- 原来超过 18 m/s 就把挥速归零的处理已移除。追踪重获、长帧和明显位姿跳变单独抑制，避免产生虚假高速击球。
- 甜区偏心会降低有效回弹；侧向摩擦影响切削与旋转。击球后保留羽毛球原有朝向，再模拟翻转稳定，不瞬间强行对齐新速度。
- 飞行采用重力、二次空气阻力、姿态相关阻力、旋转与受限的短暂侧向效应。网带擦碰和撞网采用近似响应，未模拟网线形变或羽毛细节。
- HUD 显示拍速（m/s）、初始出球速度（km/h）、发射角、旋转量（RPM）、甜区质量及过网高度；“CENTER %”是模型质量指标，不是实测击球准确率。

默认开启坐姿辅助：轻柔击球保持 1:1；接触点挥速超过 1.5 m/s 后逐渐增加速度增益，达到 5 m/s 时默认增益为 1.45 倍，并提供额外 2.5 厘米接触容错。暂停后关闭辅助，挥速增益为 1，额外接触容错缩小到 3 毫米。两种模式都不会保证过网；严格模式也仍是简化仿真。

动作提示根据接触高度、出球角度与速度、法向/切向挥速和旋转等特征区分杀球、吊球、切吊、放网、搓球，以及高远、挑球、平抽、挡球或偏心接触。**标签只解释这次接触，不反过来控制轨迹**。例如：

- 头顶球：较高击球点、较快的朝前下方正面挥拍，更可能标为 `SMASH`；减小冲量可能标为 `DROP SHOT`，带明显切向摩擦可能标为 `SLICED DROP`。
- 网前球：小幅托挡可能标为 `NET SHOT`；增加横向刷擦和旋转可能标为 `SPINNING NET`。

这些是启发式训练提示，不是经过训练或专业校准的技术动作识别模型；内部置信度也不是统计概率。只有头显和手柄，不能可靠评判真实握法、肘肩动作、身体发力链或完整正反手技术。

## 原地混合来球与专门训练

| 模式 | 来球位置（默认参数） | 球场布局 |
| --- | --- | --- |
| 混合练习 Rally（默认；键盘 1） | 拍面击球点前方 42–75 cm、惯用手侧约 18.5–25.5 cm、高度随球型变化 | 使用当前头显眼高，无需追球；可按 M 恢复固定 62 cm 来球 |
| 头顶球 Overhead（键盘 2） | 前方约 62 cm、惯用手侧 22 cm、眼睛上方 22 cm | 眼睛相对虚拟地面高 1.75 m，玩家对应球场局部 z=1.2 m，球网约在前方 2.4 m；用于中前场头顶进攻练习 |
| 网前球 NetTouch（键盘 3） | 前方约 62 cm、惯用手侧 22 cm、眼睛下方 16 cm | 眼睛相对虚拟地面高 1.5 m，玩家对应球场局部 z=2.4 m，球网约在前方 1.2 m |

高度、距离指的是**拍面中心**，不是要求手掌伸到该处。头顶训练也应使用安全的小幅动作，不要为了增加速度在电脑前全力挥拍。

混合序列包含高远、减速杀球防守、慢吊、平快球、网前来源的柔和来球，每五球各出现一次，连续不重复。发球高度、速度、弧线、近远击球点均有区别，固定种子便于对比测试。玩家回球仍完全由接触决定，标签不会预设落点。Rally 的“网前来源球”是原地练习变体，并非远离球网却能完成真正贴网放网；贴网、搓球请切 NetTouch。它不是全场随机追球模式。

模式切换只在暂停且无球飞行时进行，通过重新布置球场与发球机适应原地练习，不传送或旋转头显相机。切换会清空本轮分数；每球只移动发球机和击球环，不移动球场或视角。

## 练习规则

- 每轮 20 个球，球落地后约 2.3 秒发下一球。
- 击中 +5；落在对面界内 +10；落入金色圆形目标 +50（替代该球的界内 10 分）。
- 标记最后落点，统计击中数和连续界内球数。
- 检测球网、出界；一球只接受一次回击，避免重复记分。
- 头显或所有手柄失去追踪时自动暂停；恢复后按扳机继续。

## 约一米直径活动区的安全限制

当前按站立原地小幅挥拍设计，不安排身后球、不要求退步或跨步。**一米直径只描述站立范围，不代表手臂、手柄和头顶已有安全余量**；程序没有扫描房间，无法替你确认现实安全。开始前移开手臂挥动范围内的杯子、键盘等物品，检查头顶和左右空间，系好手柄腕带。球拍从握把向外延伸，手不用伸到圆环处；不要为了接球伸手越过真实桌面。虚拟圆环不是现实安全边界，SteamVR 的实际边界仍然有效。

球场只在校准、每轮首次开始或暂停切换训练时移动，不随转头漂移。戴上头显的瞬间不再自动锁定朝向。若发球机偏到左侧或右侧，请先坐正直视真实电脑，再按手柄上方的菜单键（不是打开 SteamVR 面板的系统键），或让游戏窗口获得焦点后按键盘 R。随后按扳机开始。重新校准会清空本轮分数；回合中正常暂停/继续不会重排球场。

可在 `Badminton Session` Inspector 调整 `Seated Reach`（0.4–0.9 m）与 `Feed Side`（0.1–0.4 m）；`Physics` 下可调整质量、阻力、回弹、摩擦、风和坐姿辅助参数。球场和 1.3 m 球网采用训练尺寸，不是正式比赛场地。

## 项目结构与验证

- `Assets/Scripts/BadmintonSession.cs`：回合、校准、训练布局、自动发球、动作反馈、分数。
- `RacketController.cs`：OpenXR 握把追踪、球拍偏移、按键、线/角速度和震动。
- `RacketImpact.cs`：短时弹簧阻尼接触、切向黏着/滑移、偏心质量和旋转。
- `PracticeFeed.cs`：可复现的混合来球与有限空间击球点。
- `ShuttlePhysics.cs`：羽毛球状态、空气阻力、翻转与旋转积分。
- `ShuttleFlight.cs` / `ShuttleMath.cs`：分步飞行、移动拍面扫掠命中、发球求解、落地/球网判断。
- `ShotClassifier.cs`：只读的技术动作特征分类。
- `Assets/Editor/BadmintonProjectBuilder.cs`：可重建场景、生成预览和 Windows 程序。
- `BadmintonRegression.cs`、`EquipmentPhysicsRegression.cs`、`PracticeFeedRegression.cs`、`SpinFlightRegression.cs`：编辑器回归检查。菜单 `Tools > Vive Shuttle VR > Run Regression Checks`；运行记录见 `Documentation/Verification.md`。
- `XRPlayModeSetup.cs` / `XRPlayModeDiagnostics.cs`：恢复旧版 Input System 的编辑器输入锁定，并输出实际 XR 运行情况。

保留本机现有的 OpenXR 1.0.2、XR Management 4.0.1、Input System 1.0.2 配置。启用了 Standalone OpenXR Loader、启动时初始化 XR、HTC Vive Controller Profile，以及编辑器 Lock Input to Game View。相关官方说明：[Unity OpenXR 1.0 输入配置](https://docs.unity3d.com/Packages/com.unity.xr.openxr@1.0/manual/input.html#locking-input-to-the-game-window)。

本项目不含 AI 对打、联网或正式比赛计分规则。物理参数和技术分类仍需实际设备试打调整；自动化检查不能代替真实握拍舒适度、追踪延迟及运动安全测试。



## 克重、磅数与切擦模型

默认质量从 5.0 g 调整为 **5.4 g**，默认 **25 lb**。可调范围 4.5–6.0 g /18–32 lb 属于游戏试验范围，不都符合比赛器材规格；BWF 羽毛球质量范围为 4.74–5.50 g。[BWF 器材规则](https://system.bwfbadminton.com/documents/folder_1_81/Statutes/CHAPTER-4---RULES-OF-THE-GAME/SECTION%204.1-%20Laws%20of%20Badminton.pdf)

加重同时影响阻力减速和转动惯性，并不等于更省力。省力由可关闭的挥速辅助独立调整。磅数影响模型线床刚度、接触时间、形变和偏心容错，不简单等同“越高磅越快”。这些是游戏标定值，不是实测商业球拍的数据；设置在本次运行有效，重启回到默认。

一次接触内部进行最多 64 个微步的弹簧阻尼、切向弹性黏着和库仑滑移计算，模拟约毫秒级的球头压入、回弹及切擦。倾斜球头受到切向作用时可产生带方向的轴向自转；切吊与正拍在同等总挥速下，不再仅靠标签区别。模型保留做功/能量约束、几何接触侧和前挥反向出球修复。

这仍是降阶近似：不是逐根球线或羽毛形变仿真，微接触中冻结惯性轴，接触段折算为宏观瞬时响应。日志的 materialSweepDeg 是材料方向扫掠估计，不是测得的真实包裹角；HUD 的接触时间与滑移比例也只是模型输出。飞行将球头翻转与轴向滚转分步计算，未实现完整陀螺刚体方程。
